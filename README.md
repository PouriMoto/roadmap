# roadmap
roadmap for finance

این یک مستند فنی کامل و ساختاریافته (Technical Documentation) از پروژه POC شماست. این فایل را می‌توانی به عنوان «نقشه راه توسعه» (Development Roadmap) و «مستندات معماری» (Architecture Doc) برای ساخت نسخه‌های بعدی یا تحویل به تیم توسعه‌دهنده استفاده کنی.

---

📑 مستندات فنی و معماری پروژه POC

نام پروژه: نقشه راه تعاملی تحلیل‌گر مالی (Financial Analyst Roadmap)
نسخه: POC v0.1.4 (مبتنی بر الگوی roadmap.sh و مکانیزم گیمیفیکیشن Duolingo)
وضعیت: آماده برای تست و توسعه (Proof of Concept)

---

۱. خلاصه مدیریتی (Executive Summary)

این پروژه یک POC (اثبات مفهوم) برای نمایش نقشه راه شغلی در حوزه مالی است. هدف اصلی، جایگزینی لیست‌های خشک آموزشی با یک گراف مسیر (Path Graph) است که کاربر را از سطح مبتدی تا پیشرفته هدایت می‌کند. مزیت رقابتی این POC، ترکیب ساختار درختی نقشه‌های راه با مکانیزم «رد شدن از سطح» (Skip Level) به سبک اپلیکیشن دولینگو و همچنین سیستم مشارکت جامعه (Community-Driven) برای پیشنهاد منابع است.

---

۲. فناوری‌های استفاده شده (Tech Stack)

این پروژه به صورت Zero-Build (بدون نیاز به Webpack یا Vite) طراحی شده تا در سریع‌ترین زمان ممکن روی هر مرورگری اجرا شود.

لایه (Layer) تکنولوژی دلیل انتخاب
ساختار (HTML) HTML5 ساده و سبک
استایل (CSS) Vanilla CSS3 + CSS Variables عدم وابستگی به Tailwind یا Bootstrap برای کاهش حجم و کنترل کامل روی تم
منطق (JS) React 18 (CDN) مدیریت State های پیچیده (منابع، وضعیت کاربر، ادمین)
کامپایلر Babel Standalone اجرای مستقیم کدهای JSX در مرورگر بدون نیاز به Node.js
آیکون‌ها Tabler Icons (Webfont) آیکون‌های خطی مدرن، سبک و کاملاً متناسب با UI مدرن
رندر متن Marked.js تبدیل Markdown به HTML برای توضیحات گره‌ها
دیتابیس (موقت) LocalStorage ذخیره‌سازی وضعیت کاربر، منابع و پیشنهادات در سمت کلاینت برای POC

۳. معماری اطلاعات (Information Architecture)

داده‌ها در این POC به سه بخش اصلی تقسیم می‌شوند:

الف) سطوح شغلی (Stages)

نردبان شغلی به سه بخش تقسیم شده که در قالب یک تایم‌لاین عمودی نمایش داده می‌شود:

1. Junior (مبتدی): شروع مسیر، مفاهیم پایه (حسابداری، اکسل مقدماتی).
2. Mid-Level (متوسط): تحلیل‌گر حرفه‌ای (مدل‌سازی مالی، تحلیل نسبت‌ها، پایتون).
3. Senior (پیشرفته): استراتژیست (ارزش‌گذاری DCF، مدیریت ریسک، CFA).

ب) گره‌ها (Nodes / Skills)

هر گره نماینده یک مهارت است و شامل: عنوان، مدت زمان تخمینی، دسته‌بندی (Hard Skill, Soft Skill, Tool, Certification, Business) و توضیحات Markdown است.

ج) منابع (Resources)

منابع داخل هر گره قرار می‌گیرند و دارای متادیتای غنی هستند:

· نوع (Type): دوره، ویدیو، کتاب، فایل (اکسل/PDF)، مقاله و...
· سطح منبع (Level): مبتدی، متوسط، پیشرفته (برای فیلتر کردن داخل شیت).
· قیمت (Pricing): رایگان، پولی، نیمه‌رایگان.
· زبان (Language): فارسی، انگلیسی.
· منبع (Source): تیم محتوا (Admin) یا جامعه (User).

---

۴. معماری UI/UX (طراحی رابط و تجربه کاربری)

الف) اصول طراحی

· Mobile-First: تمام دکمه‌ها حداقل ۴۴ پیکسل (اندازه استاندارد لمس) هستند.
· Bottom Sheet: استفاده از شیت‌های کشویی از پایین صفحه (الگوی Material Design) به جای باز کردن صفحات جدید.
· نردبان بصری (Visual Hierarchy): خط عمودی در سمت راست و دایره‌های وضعیت (سبز/زرد) که حس پیشرفت را به کاربر القا می‌کند.
· رنگ‌بندی معنادار: رنگ‌ها در سه سطح اصلی (سبز برای مبتدی، نارنجی برای متوسط، قرمز برای پیشرفته) و رنگ‌های اختصاصی برای هر دسته‌بندی مهارت.

ب) مکانیزم‌های تعاملی (Interactions)

· Skip Level (دکمه دولینگو): در انتهای هر سطح، یک دکمه بزرگ وجود دارد. اگر کاربر روی آن بزند، تمام گره‌های آن سطح با تایید کاربر (Alert) به وضعیت «تکمیل شده» می‌روند.
· Accordion: منابع درون شیت بر اساس سطح (مبتدی/متوسط/پیشرفته) به صورت آکاردئونی باز و بسته می‌شوند.
· Voting System: کاربران می‌توانند به منابع لایک/دیس‌لایک بدهند (👍/👎).

۵. جریان‌های کاربری (User Flows)

جریان کاربر عادی (User)

1. ورود به صفحه اصلی.
2. مشاهده نردبان (از بالا به پایین).
3. کلیک روی یک گره (مثلاً مدل‌سازی مالی).
4. باز شدن Bottom Sheet → مشاهده توضیحات + منابع.
5. کلیک روی منابع → هدایت به لینک خارجی.
6. تغییر وضعیت گره (ندیده‌ام / در حال یادگیری / تکمیل شده) → نوار پیشرفت بالای صفحه آپدیت می‌شود.
7. استفاده از دکمه «رد شدن از سطح».

جریان تیم محتوا / ادمین (Admin Flow)

1. کلیک روی تب «ادمین» در هدر.
2. ورود رمز عبور (کد Hardcode شده در این نسخه).
3. تب مدیریت گره‌ها: امکان ساخت گره جدید (انتخاب سطح، دسته‌بندی، عنوان) و حذف گره‌های قبلی.
4. تب افزودن محتوا: (ساده‌ترین روش ممکن) انتخاب یک گره از لیست → پر کردن فرم منبع (نوع، لینک، سطح، قیمت) → ثبت. منبع بلافاصله در شیت کاربر نمایش داده می‌شود.
5. تب در انتظار: تایید یا رد منابعی که توسط کاربران پیشنهاد داده شده‌اند.

۷. مسیر توسعه (Roadmap to Production)

از آنجا که این یک POC است، برای تبدیل آن به یک محصول واقعی (Production-Ready) این مراحل باید طی شود:

فاز ۱: زیرساخت و بک‌اند (Backend)

· انتقال دیتا از LocalStorage به دیتابیس واقعی (PostgreSQL + Prisma یا Supabase).
· پیاده‌سازی سیستم احراز هویت (Authentication) با Clerk یا NextAuth.
· پیاده‌سازی سیستم نقش‌ها (Role-Based Access Control) تا فقط ادمین‌های واقعی به پنل دسترسی داشته باشند.

فاز ۲: بهبود UI/UX و انیمیشن

· افزودن انیمیشن‌های نرم (Framer Motion) برای باز شدن Bottom Sheetها و حرکت بین گره‌ها.
· افزودن حالت Dark Mode.
· پیاده‌سازی سیستم Drag & Drop برای ادمین جهت تغییر ترتیب گره‌ها.

فاز ۳: گیمیفیکیشن و شخصی‌سازی

· سیستم مسیر پیشنهادی هوشمند: وقتی کاربر یک گره را تمام کرد، گره بعدی به صورت خودکار هایلایت شود.
· اختصاص نشان (Badge) به کاربرانی که از یک سطح رد می‌شوند (مثل دولینگو).
· سیستم کامنت‌گذاری برای منابع (به جای فقط لایک و دیس‌لایک).

فاز ۴: مقیاس‌پذیری (Scalability)

· تبدیل دیتای نقشه راه از فایل JSON به یک CMS (مانند Sanity یا Strapi) تا ادمین‌ها بدون کد بتوانند نقشه‌های جدید (مثلاً وکیل، برنامه‌نویس) بسازند.
· ایجاد API برای اتصال به سایر اپلیکیشن‌ها.
